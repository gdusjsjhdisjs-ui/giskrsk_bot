# Инструкция для DeepSeek: внедрение AI GIS Copilot в «ГИС Красноярье»

## Цель

Развить существующий Telegram-бот и WebGIS-карту без переписывания проекта. Сделать AI не отдельным чатом, а помощником, который понимает выбранный объект или область карты, вызывает существующие GIS-функции, анализирует подтверждённые данные и объясняет результат.

Главный пользовательский сценарий:

> Пользователь выбирает участок или область → задаёт вопрос обычным языком → система включает нужные источники, выполняет GIS-анализ кодом → DeepSeek объясняет результат и показывает источники, ограничения и следующие действия.

---

## 1. Обязательные правила разработки

1. Сначала изучи существующий код и найди функции, которые можно переиспользовать.
2. Не переписывай целиком `webapp/index.html` и не меняй существующий дизайн без необходимости.
3. Все изменения делай небольшими этапами.
4. Перед каждым этапом сначала покажи diff-план и дождись подтверждения.
5. Не помещай DeepSeek API key и NextGIS token в браузерный JavaScript.
6. WebApp обращается к DeepSeek только через FastAPI backend.
7. Геометрические расчёты выполняются MapLibre, Turf.js, Shapely/PostGIS, но не нейросетью.
8. DeepSeek получает уже рассчитанные факты и только объясняет или выбирает допустимые инструменты.
9. Не выдумывай ID ресурсов NextGIS, свойства GeoJSON, нормы ПЗЗ и API endpoints.
10. Сохраняй обратную совместимость Telegram-бота, карты, магазина, подписок и клиппинга.
11. Каждая новая функция должна иметь обработку ошибок, fallback и тесты.
12. AI-ответ не является официальным юридическим заключением.

---

## 2. Общая архитектура

```text
WebApp / Telegram
        ↓
AI Orchestrator в FastAPI
        ↓
Intent + извлечение сущностей
        ↓
Выбор разрешённых GIS-инструментов
        ↓
ParcelService / NextGIS / GeoJSON / поиск документов
        ↓
Evidence Pack с фактами и источниками
        ↓
DeepSeek формирует структурированное объяснение
        ↓
Проверка JSON, ссылок, чисел и уверенности
        ↓
Карточка в WebApp / сообщение Telegram / PDF
```

### DeepSeek не должен напрямую управлять картой

DeepSeek возвращает только разрешённые команды в JSON. Frontend или backend проверяет JSON и выполняет команды.

Пример:

```json
{
  "intent": "analyze_selected_area",
  "actions": [
    {"tool": "calculate_area"},
    {"tool": "intersect_visible_layers"},
    {"tool": "summarize_zone_distribution"}
  ],
  "requested_output": "short_report"
}
```

Разрешать только инструменты из whitelist. Любая неизвестная команда отклоняется.

## 3. Технология №1 — AI-комментарий по клику на карту

### Сценарий

1. Пользователь нажимает на участок, ПЗЗ, ЗОУИТ, красную линию или объект генплана.
2. Существующая шторка показывает свойства.
3. В шторке появляется кнопка `✨ Объяснить`.
4. Frontend отправляет backend:
   - тип слоя;
   - ID/свойства выбранного feature;
   - координаты клика;
   - кадастровый номер, если есть;
   - источник и дата слоя.
5. Backend очищает свойства, получает дополнительные сведения и создаёт Evidence Pack.
6. DeepSeek возвращает краткое объяснение.

### Формат ответа

```json
{
  "summary": "Короткое объяснение объекта",
  "facts": [
    {"label": "Зона", "value": "Ж-1", "source_id": "pzz_krsk"}
  ],
  "risks": [],
  "missing_information": [],
  "next_actions": [
    {"id": "open_documents", "label": "Найти регламент зоны"}
  ],
  "confidence": 0.82,
  "disclaimer": "Предварительный информационный анализ"
}
```

### Первая реализация

- Не добавлять память диалога.
- Анализировать только один выбранный feature.
- Ограничить ответ 1500–2000 символами.
- При недоступности DeepSeek показывать исходные свойства объекта.

---

## 4. Технология №2 — диалог с выделенной областью

### Сценарий

Пользователь рисует полигон или прямоугольник и спрашивает:

- «Какие зоны здесь преобладают?»
- «Есть ли ограничения?»
- «Сколько объектов попало в область?»
- «Какая часть территории относится к жилым зонам?»

### Реализация

1. Переиспользовать существующий инструмент площади/клиппинга.
2. Получить GeoJSON выбранной области.
3. Backend выполняет пересечения с доступными векторными слоями.
4. Для каждого слоя рассчитать:
   - количество объектов;
   - площадь пересечения;
   - процент выбранной территории;
   - основные категории;
   - ошибки и неполные данные.
5. DeepSeek получает только агрегированный результат.

```json
{
  "selected_area_m2": 125400,
  "layers": [
    {
      "layer_id": "pzz_krsk",
      "coverage_percent": 83.4,
      "categories": [
        {"code": "Ж-1", "area_m2": 78000, "percent": 62.2}
      ]
    }
  ],
  "unchecked_layers": ["zouit"],
  "data_timestamp": "2026-07-23"
}
```

### Ограничение

TMS-тайлы являются изображением и не подходят для точного пространственного анализа. Для анализа ЗОУИТ/кадастра нужен vector API, feature endpoint или локальный векторный слой. Если доступен только TMS — явно писать «слой отображён, но не проверен аналитически».

## 5. Технология №3 — поиск и фильтрация обычным языком

### Примеры

- «Покажи только жилые зоны».
- «Найди участки рядом с Дивногорском».
- «Оставь производственные зоны и скрой остальные».
- «Покажи территорию в радиусе 2 км от этой точки».

### Механика

DeepSeek преобразует вопрос в безопасный `MapCommand`, но не создаёт JavaScript-код.

```json
{
  "command": "filter_layer",
  "layer_id": "pzz_divn",
  "conditions": [
    {"property": "urban_index", "operator": "starts_with", "value": "Ж"}
  ],
  "fit_to_results": true
}
```

### Whitelist

Разрешить только:

- `show_layer`;
- `hide_layer`;
- `filter_layer`;
- `clear_filter`;
- `fit_to_results`;
- `set_center`;
- `set_zoom`;
- `open_feature`;
- `draw_buffer`;
- `start_comparison`.

Проверять, что `layer_id`, property и operator существуют в конфигурации. Не передавать ответ модели напрямую в `eval()`.

---

## 6. Технология №4 — сравнение участков

### Сценарий

Пользователь добавляет 2–5 участков в сравнение. Система формирует таблицу:

- зона ПЗЗ;
- ВРИ;
- площадь;
- кадастровая стоимость;
- найденные ограничения;
- пересечение с красными линиями;
- полнота данных;
- дата источников.

DeepSeek объясняет различия, но не назначает субъективный рейтинг без прозрачных правил.

### Скоринг

Если нужен рейтинг, формулу задаёт код и показывает пользователю:

```text
Итог = полнота данных × 0.20
      + отсутствие найденных ограничений × 0.30
      + соответствие цели пользователя × 0.35
      + актуальность источников × 0.15
```

Весовые коэффициенты должны быть настраиваемыми. «Ограничение не найдено» не означает «ограничений нет».

---

## 7. Технология №5 — карта рисков и полноты проверки

Вместо юридической оценки использовать два независимых индикатора.

### Индикатор найденных факторов

- зелёный: критические факторы в подключённых источниках не найдены;
- жёлтый: найдены факторы, требующие проверки;
- красный: найдено подтверждённое пересечение/противоречие;
- серый: данных недостаточно.

### Индикатор полноты

```text
ПЗЗ              ✅
ВРИ              ✅
ЗОУИТ            ⚠️ только визуальный TMS
Красные линии    ✅
Генплан          ✅
Документы        ❌ не загружены
Актуальность     ⚠️ дата не подтверждена

Проверено: 4 из 7 источников
```

DeepSeek объясняет индикатор, но статус рассчитывается кодом.

---

## 8. Технология №6 — AI-поиск по документации

### Сценарий

- «Найди максимальную высоту для зоны Ж-1».
- «Где написано про минимальные отступы?»
- «Каким решением изменили ПЗЗ?»

### MVP

1. Реестр документов с муниципалитетом, типом, редакцией, датой и URL.
2. Извлечение текста PDF с сохранением страниц.
3. OCR для сканов.
4. Чанки по разделам и страницам.
5. PostgreSQL full-text search.
6. Позже — embeddings/pgvector и гибридный поиск.
7. DeepSeek получает 5–8 найденных фрагментов.
8. Каждый вывод содержит документ, страницу, короткую цитату и ссылку.

Если точный фрагмент не найден, модель обязана это сообщить. Запрещено создавать цитату из памяти.

---

## 9. Технология №7 — «Что изменилось?»

### Источники сравнения

- две версии GeoJSON;
- две версии документа ПЗЗ;
- предыдущий и новый snapshot участка;
- изменение атрибутов feature в NextGIS.

### Код рассчитывает

- добавленные/удалённые объекты;
- изменённую геометрию;
- изменённые атрибуты;
- площадь изменений;
- расстояние от отслеживаемого участка.

### DeepSeek объясняет

- что изменилось;
- может ли изменение относиться к выбранному участку;
- какие документы или поля необходимо проверить;
- уровень уверенности.

Не отправлять модели целые GeoJSON. Передавать diff и агрегаты.

---

## 10. Технология №8 — умный снимок и AI-отчёт

Пользователь нажимает `📷 Отчёт`.

Система создаёт:

1. снимок карты с выбранным объектом;
2. легенду активных слоёв;
3. таблицу подтверждённых фактов;
4. найденные факторы и непроверенные источники;
5. краткий AI-комментарий;
6. ссылки на документы;
7. дату создания и предупреждение.

Для PNG проверить `preserveDrawingBuffer`, CORS raster-тайлов и отсутствие секретов в URL. Для профессионального результата предпочтительнее серверный PDF из Jinja2/WeasyPrint.

---

## 11. Технология №9 — персональные уведомления

Пользователь выбирает участок и интерес:

- изменение ПЗЗ;
- появление ограничения;
- новый документ;
- изменение объекта рядом;
- новый аукцион в заданном радиусе.

Backend сравнивает snapshots и создаёт Change Evidence. DeepSeek формирует короткое объяснение:

```text
Что изменилось → почему это может быть важно → расстояние до участка → источник → действие
```

Не отправлять уведомление, если изменился только технический порядок полей или хэш файла без изменения данных.

## 12. Технология №10 — следующее лучшее действие

После каждого результата показывать максимум три контекстные кнопки:

- `Найти регламент зоны`;
- `Проверить ограничения`;
- `Сравнить участок`;
- `Создать отчёт`;
- `Следить за изменениями`;
- `Открыть на карте`.

DeepSeek может предложить действия, но frontend принимает только ID из whitelist.

## 15. Порядок внедрения

### Этап 1 — AI по клику

Самый быстрый и наглядный результат:

- кнопка в существующей шторке;
- endpoint `explain-feature`;
- Evidence Pack;
- структурированный ответ;
- fallback без AI;
- unit tests.

### Этап 2 — анализ выделенной области

- переиспользовать рисование площади;
- backend spatial analysis;
- агрегаты по слоям;
- краткое объяснение.

### Этап 3 — естественные команды карты

- JSON-схема MapCommand;
- whitelist;
- фильтрация ПЗЗ;
- управление видимостью слоёв.

### Этап 4 — документы

- реестр;
- парсинг/OCR;
- полнотекстовый поиск;
- цитаты;
- затем гибридный RAG.

### Этап 5 — сравнение и отчёты

- список сравнения;
- прозрачный скоринг;
- PDF;
- мониторинг изменений.

## 18. Критерии готовности AI GIS Copilot

- AI знает, какой объект или область выбраны.
- Все числа получены из данных или GIS-инструментов.
- Для основных фактов указаны источники и дата.
- Непроверенные TMS-слои обозначаются как непроверенные.
- Нет прямого вызова DeepSeek из браузера.
- Нет `eval()` и выполнения сгенерированного кода.
- Неизвестные команды карты отклоняются.
- Есть fallback без нейросети.
- Существующие функции карты не сломаны.
- Есть тесты и способ ручной проверки.
- Пользователь понимает не только результат, но и полноту проверки.

---

## Итоговая концепция

AI GIS Copilot должен работать по формуле:

> **выбор на карте → безопасные инструменты → проверяемые факты → объяснение DeepSeek → источники → следующее действие.**

Именно такая интеграция даст проекту инновационность без полного изменения текущей архитектуры.
