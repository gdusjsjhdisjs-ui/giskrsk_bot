## 1. ПОЛНАЯ КАРТИНА ПРОЕКТА «ГИС Красноярье»

### 1.1. Что это вообще такое

**ГИС Красноярье** — это коммерческий WebGIS-сервис для Красноярского края.

Простое объяснение: представьте Google Карты, но вместо дорог и ресторанов там показано — **где что можно строить**. Жёлтым — можно дом построить, зелёным — только огороды, синим — магазины разрешены, красным — нельзя ничего.

Это называется **карта зон ПЗЗ** (Правила землепользования и застройки). Государство утверждает для каждой территории правила: на этом участке можно построить жилой дом, на соседнем — только гараж, а дальше вообще заповедник.

**Проблема:** сейчас, чтобы узнать, что можно строить на участке, надо:
1. Найти на сайте администрации PDF с картой зонирования
2. Геопривязать и понять, куда именно попадает участок
3. Найти в тексте ПЗЗ расшифровку зоны
4. Понять: «Можно строить или нет?»

Это 1-3 часа работы даже для профессионала.

**Наше решение:** мы собираем все эти данные в одном месте, накладываем на интерактивную карту и делаем Telegram-бота. Кликнул на участок — увидел всё за секунду.

### 1.3. Как всё связано друг с другом

**Путь данных от источника до клиента:**

```
ГОСУДАРСТВО                  МЫ                       КЛИЕНТ
│                           │                        │
ГИСОГД ──→ Python скрипты ──→ NextGIS Web ──→ Веб-карта в браузере
(ПЗЗ)     (выгрузка,        (облачное          │
│          spatial join)     хранилище)         ├──→ Telegram-бот
NSPD ───────────────────────────────────       │    (проверка, подписка,
(кадастр)                                      │     пакетная обработка)
│                                              │
Сайты админи- ──→ QGIS ──→ GeoJSON ────────    └──→ PDF-справка
```

**Ключевая точка:** все данные сходятся в NextGIS Web. Оттуда их забирает и веб-карта, и Telegram-бот. Один источник правды.

### 1.6. Где бот вписывается в картину

Бот — это **входная точка для клиента** и **инструмент ежедневного использования**. Не замена веб-карты, а её дополнение.

**Что бот делает лучше карты:**
- Быстрая проверка: отправил кадастровый номер → получил ответ. Не надо открывать браузер
- Уведомления: бот сам пришлёт, если по участку что-то изменилось
- Пакетная проверка: загрузил CSV → получил Excel. Карта так не умеет
- Платежи: купил подписку не отходя от Telegram

**Что карта делает лучше бота:**
- Визуальное представление: все зоны цветом на одной карте
- Пространственный анализ: кликнул → увидел соседние участки
- Сложные запросы: покажи все участки в зоне Ж-1 площадью 5-10 соток

**Связка:** бот присылает ссылку «Открыть на карте» → клиент переходит на веб-карту с этим же участком. Одно дополняет другое.

В России есть **только один прямой конкурент** — ГИС «Полигон» из Иркутска. В городах-миллионниках (Красноярск, Новосибирск, Екатеринбург, Казань, Уфа) качественных zoning-сервисов нет вообще.

- Что есть: ПЗЗ, генплан, красные линии, ЗОУИТ, кадастр подложкой

## 2. TELEGRAM-БОТ (подробное описание)

### 2.1. Что делает бот в проекте

Telegram-бот — это интерфейс для быстрого доступа к данным ГИС Красноярье. Он не заменяет веб-карту, а дополняет её.

**Источник функций:** все перечисленные ниже возможности взяты из Obsidian-файлов проекта — `00 - ФУНДАМЕНТ.md`, `01 - ФУНКЦИОНАЛ.md`, `ПЛАН_Telegram_бота.md`, `бота_архитектура_от_SellerGPT.md`, `ТЗ_полная_спецификация.md`, `08-Услуги_и_продукты.md`.

Бот даёт возможность:

**1. 🔍 Проверить участок по кадастровому номеру — за 5 секунд**
Пользователь вводит КН → бот показывает: зону ПЗЗ, ВРИ, площадь, кадастровую стоимость, ограничения. Данные из NextGIS Web с кэшированием в Redis. *(Источник: все файлы)*

**2. 📍 Проверка по геопозиции**
Пользователь отправляет геоточку (где стоит) → бот определяет зону ПЗЗ вокруг координат. Для поля — стоишь на участке, сразу видишь что можно строить. *(Источник: `01 - ФУНКЦИОНАЛ.md`, `00 - ФУНДАМЕНТ.md`, `бота_архитектура_от_SellerGPT.md`)*

**3. 💳 Купить подписку и управлять ей — не отходя от Telegram**
Inline-кнопка «Оплатить» → ЮKassa → webhook → подписка активна. Никаких сайтов и звонков. *(Источник: все файлы)*

**4. 📤 Пакетная проверка (batch screening)**
Загрузил CSV с сотней кадастровых номеров → бот обрабатывает асинхронно (ARQ worker) → выдаёт Excel-файл с колонками: КН, зона ПЗЗ, ВРИ, площадь, стоимость, статус, ошибка. *(Источник: `ПЛАН_Telegram_бота.md`, `бота_архитектура_от_SellerGPT.md`)*

**5. 🔔 Отслеживание изменений ПЗЗ**
Подписался на участок → бот раз в день сверяет данные через NextGIS API → при изменении зоны, ВРИ или стоимости шлёт уведомление. *(Источник: `ПЛАН_Telegram_бота.md`, `бота_архитектура_от_SellerGPT.md`)*

**6. 📄 PDF-справка по участку**
Подробный отчёт (2-3 стр A4): зона ПЗЗ, параметры застройки, кадастровая стоимость, карта-врезка. Можно отправить клиенту. WeasyPrint + Jinja2. *(Источник: `бота_архитектура_от_SellerGPT.md`, `08-Услуги_и_продукты.md`)*

**7. 📊 Мониторинг аукционов**
Бот отслеживает свежие земельные аукционы (torgi.gov.ru и сайты администраций), присылает кадастровые номера → пользователь вбивает в карту → видит зону → принимает решение о покупке. Фильтры: по НП, району, категории земель. *(Источник: `00 - ФУНДАМЕНТ.md` — ключевая связка «Бот мониторит аукционы → карта → решение»; `01 - ФУНКЦИОНАЛ.md`)*

**8. 🔄 Конвертер геоформатов**
Пользователь загружает GeoJSON/Shapefile/KML/GPKG → выбирает формат → бот конвертирует и отдаёт файл. Для кадастровых инженеров, которые работают в разных ГИС. *(Источник: `ПЛАН_Telegram_бота.md`, Этап 3: services/geo_converter.py)*

**9. 📦 Векторные выгрузки (покупка)**
Купить GeoJSON/GeoPackage слоя ПЗЗ через бота — 3 000–5 000 ₽ за район. Кадастровый инженер получает готовый файл для QGIS без разбора с ГИСОГД. *(Источник: `08-Услуги_и_продукты.md`, `ПЛАН_Telegram_бота.md`)*

**10. 📝 Регистрация пользователя при первом входе**

## 4. КАК РАБОТАЕТ СИСТЕМА (общая схема)

### 4.1. Компоненты

```
Пользователь Telegram
        │
        ▼
┌───────────────────┐
│  Telegram Bot     │  ← aiogram 3 (обработка команд, клавиатуры)
│  (бот-фреймворк)  │
└────────┬──────────┘
         │
         ▼
┌───────────────────┐
│  FastAPI Backend  │  ← Получает запросы от бота
│  (веб-сервер)     │     Общается с БД, Redis, NextGIS, ЮKassa
└────────┬──────────┘
         │
    ┌────┼────┬────┐
    ▼    ▼    ▼    ▼
┌─────┐ ┌──┐ ┌──┐ ┌──────┐
│Post-│ │Re-│ │  │ │NextGIS│
│greSQL│ │dis│ │ARQ│ │ Web  │
│(БД) │ │(кэш│ │(фон│ │(ПЗЗ) │
└─────┘ └──┘ └──┘ └──────┘
```

### 4.2. База данных (PostgreSQL)

Бот использует **10 таблиц** для хранения всех данных:

1. **users** — пользователи (telegram_id, username, роль, дневной лимит)
2. **payments** — все платежи (сумма, статус, idempotency_key)
3. **payment_webhook_events** — входящие уведомления от ЮKassa (защита от дублей)
4. **subscriptions** — подписки (тариф, срок, статус)
5. **tracked_objects** — отслеживаемые участки
6. **change_events** — история изменений по участкам
7. **notifications** — уведомления пользователям
8. **batch_jobs** — задания пакетной проверки
9. **batch_items** — результаты проверки каждого номера
10. **layer_sync_state** — состояние слоёв ПЗЗ (версия, дата)

### 4.3. Откуда берутся данные ПЗЗ

Данные берутся из NextGIS Web (zimin-maplive0000.nextgis.com). Там хранятся слои:
- Слой участков с ПЗЗ (зона, ВРИ, площадь, стоимость)
- Слой зон ПЗЗ (полигоны с кодами и названиями)

В NextGIS данные загружаются из:
- Государственной системы ГИСОГД (agate.gisogd24.ru) — ПЗЗ, генпланы, красные линии
- НСПД (nspd.gov.ru) — кадастровые участки

### 4.4. Платежи

Платежи проходят через **ЮKassa** (yookassa.ru):
1. Бот создаёт платёж в ЮKassa
2. ЮKassa присылает ссылку на оплату
3. Пользователь оплачивает
4. ЮKassa присылает webhook-уведомление
5. Бот проверяет: не дубликат ли? Если да — игнорирует
6. Активирует подписку

### 4.5. Кэширование

Redis используется для:

## 8. ИНТЕГРАЦИЯ С DEEPSEEK (AI-СЛОЙ БОТА)

### 8.1. Что это и зачем

У нас есть **собственный API DeepSeek** (модели v4 Pro и v4 Flash). Это не какой-то сторонний конструктор вроде n8n — DeepSeek встраивается прямо в код бота как сервис. Бот получает **настоящий LLM-мозг**, а не цепочку готовых блоков.

**В чём разница:**
| | n8n / flow-конструкторы | Наш подход (DeepSeek API в коде) |
|--|------------------------|----------------------------------|
| Гибкость | Только готовые ноды и коннекторы | Любая логика на Python |
| Контекст | Ограничен схемой потока | Весь контекст пользователя + данные ПЗЗ |
| Цена | Подписка на платформу (~$20-50/мес) | Только стоимость токенов |
| Контроль | Зависимость от платформы | Полный код у нас |
| Модели | Только что доступно в платформе | Любая модель DeepSeek (Pro/Flash) |

### 8.2. Где DeepSeek работает в боте

#### 🔧 AI-консультант по земле

Пользователь задаёт вопрос напрямую, бот отвечает с учётом данных ПЗЗ:

```
Пользователь: «На участке 24:11:0330102:814 можно построить два дома?»
→ Бот проверяет КН через NextGIS → получает зону Ж-1, площадь 1200 м²
→ Отправляет в DeepSeek: 
   «Участок 24:11:0330102:814, зона Ж-1 (ИЖС), 1200 м²,
    параметры: этажность до 3, % застройки до 30%, отступы 3 м.
    Вопрос: можно ли построить два дома?»
→ DeepSeek отвечает: «В зоне Ж-1 разрешён один индивидуальный жилой дом.
   При 1200 м² и 30% застройки возможная площадь дома до 360 м².
   Два отдельных дома — нет. Один дом + гостевой домик/хозпостройки — да.»
→ Пользователь получает ответ с ссылками на источники
```

#### 🔧 Анализ аукционов

```
Пользователь: «Этот участок на аукционе — адекватная цена?»
→ Бот парсит аукцион → данные участка → DeepSeek
→ DeepSeek: анализ рынка, сравнение с соседними, рекомендация
```

#### 🔧 Объяснение юридических терминов

```
Пользователь: «Что такое условно разрешённый вид использования?»
→ DeepSeek отвечает простым языком с примерами из Красноярского края
```

#### 🔧 Генерация описания участка для объявления

```
Пользователь: «Напиши описание для продажи участка 24:11:0330102:814»
→ DeepSeek: тексты для Авито/Циан с данными ПЗЗ, инфраструктурой, районом
```

### 8.3. Как это устроено технически

**Архитектура:**
```
Пользователь → aiogram handler → AI Service → DeepSeek API (HTTP) → ответ
                                  ↑
                            Контекст из БД:
                            - Данные участка (NextGIS)
                            - Зона ПЗЗ и параметры
                            - История диалога (Redis)
                            - Промт-шаблоны (jurist, investor, builder)
```

**Где живёт:**
- `app/services/ai_service.py` — сервис-обёртка DeepSeek
- `app/services/prompts/` — папка с промт-шаблонами для разных сценариев
- `app/bot/handlers/ai.py` — хендлер, принимающий голосовые/текстовые запросы

**Как работает сервис:**
```python
class AIService:
    def __init__(self, api_key: str, model: str = "deepseek-chat"):
        self.client = OpenAI(base_url="https://api.deepseek.com", api_key=api_key)
        self.model = model

    async def ask(self, user_query: str, context: dict) -> str:
        """
        1. Берёт промт-шаблон под сценарий (jurist/investor/etc)
        2. Подставляет данные участка, зоны ПЗЗ, параметры
        3. Отправляет в DeepSeek API
        4. Возвращает ответ
        """
```

**Промт-шаблоны:**
```
jurist.md — «Ты — юрист по земельному праву Красноярского края.
            Отвечай на основе ЗК РФ, ГрК РФ, ПЗЗ конкретного района.
            Ссылайся на статьи законов.»

investor.md — «Ты — аналитик рынка земли Красноярска.
              Оценивай инвестиционную привлекательность участка.
              Сравнивай с рыночными ценами в районе.»

builder.md — «Ты — архитектор-консультант.
             Расскажи, что можно построить на участке.
             Учитывай параметры ПЗЗ: этажность, % застройки, отступы.»
```

### 8.4. Модели DeepSeek

| Модель | Для чего | Когда использовать |
|--------|----------|-------------------|
| **DeepSeek v4 Flash** | Быстрые ответы — проверка участка, простые вопросы | Стандартный режим, массовые запросы |
| **DeepSeek v4 Pro** | Сложные юридические консультации, анализ аукционов, генерация документов | Для Premium-пользователей |

### 8.5. Что даёт бизнесу

1. **AI-консультант** — пользователи получают ответы сразу, не ждут Ярослава
2. **Дополнительный доход** — можно продавать AI-консультации как премиум-фичу
3. **Конкурентное преимущество** — ни у Полигона, ни у российских аналогов такого нет
4. **Масштабирование** — AI отвечает 24/7, не требует присутствия человека

**Когда внедрять:** после MVP (бота + подписок). AI-слой не входит в первый запуск, но архитектура должна быть заложена сразу — чтобы не переписывать handlers потом.
