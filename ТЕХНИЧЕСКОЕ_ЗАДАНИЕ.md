# 📋 ТЕХНИЧЕСКОЕ ЗАДАНИЕ — ГИС Красноярье (Telegram Bot + WebGIS)

> Версия: 1.0 (2026-07-25)
> Формат: инструкция для AI-кодера в VS Code
> Режим: полная автономная работа над проектом

---

## 🎯 ЦЕЛЬ ПРОЕКТА

Коммерческий WebGIS-сервис для Красноярского края. Telegram-бот + веб-карта для проверки земельных участков по ПЗЗ (Правила землепользования и застройки), кадастру, ЗОУИТ. Продажа подписок на веб-карту и геоданных.

**Стек:** Python 3.11+, aiogram 3.17, FastAPI 0.115, SQLAlchemy 2.0 (async), PostgreSQL 16 / SQLite, Redis 7, MapLibre GL JS 4.7

## 📌 ЗАДАЧА 11: AI GIS Copilot

**Файлы:** новые: `app/services/ai_orchestrator.py`, `app/bot/handlers/ai_copilot.py`

### Концепция:
Не отдельный чат, а помощник который:
1. Понимает выбранный объект или область на карте
2. Вызывает существующие GIS-функции
3. Анализирует подтверждённые данные
4. DeepSeek объясняет результат

### Архитектура:
```
WebApp/Telegram → AI Orchestrator → Intent Detection
    → Выбор разрешённых GIS-инструментов
    → ParcelService / NextGIS / PostGIS / GeoJSON
    → Evidence Pack (факты + источники)
    → DeepSeek формирует ответ
    → Пользователь
```

### Инструменты AI-ассистента:
- `get_parcel(cadnum)` — информация об участке
- `find_pzz_zone(lat, lon)` — ПЗЗ зона по координатам
- `intersect_layers(geometry)` — пересечение со всеми слоями
- `calculate_area(geometry)` — площадь
- `buffer_analysis(geometry, meters)` — буферный анализ
- `search_documents(query)` — поиск по документам ПЗЗ
- `compare_versions(cadnum)` — история изменений

### Формат ответа:
```json
{
  "summary": "Короткое объяснение",
  "facts": [{"label": "Зона", "value": "Ж-1", "source": "pzz_krsk"}],
  "risks": ["Зона допускает только ИЖС"],
  "missing_information": ["Проверить ЗОУИТ"],
  "next_actions": ["Проверить в Росреестре"],
  "confidence": "high"
}
```

# ЧАСТЬ 4: ПРАВИЛА РАБОТЫ ДЛЯ AI-КОДЕРА

## 4.1. Общие правила
1. **Сначала прочитать** существующий код — не переписывать с нуля
2. **Переиспользовать** существующие функции, сервисы, репозитории
3. **Не удалять** работающий функционал без команды
4. **Не выдумывать** ID ресурсов NextGIS, свойства GeoJSON, API endpoints
5. **Не помещать** секреты (токены, ключи) в браузерный JS или публичный репозиторий
6. **Геометрию** считать через Shapely/PostGIS/Turf.js — не через нейросеть
7. **Изменения** делать небольшими, проверяемыми этапами
8. **После каждого изменения** написать: какие файлы изменены, как проверить

## 4.2. Безопасность
1. API-ключи и токены — только в `.env` (который в .gitignore)
2. DeepSeek API key — НЕ вставлять в index.html (GitHub Pages публичен)
3. Frontend → FastAPI (не прямой вызов DeepSeek)
4. CORS — не `allow_origins=["*"]` в production
5. Логи без токенов, паролей, персданных
6. Не возвращать пользователю внутренние исключения
